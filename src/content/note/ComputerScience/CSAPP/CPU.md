## 单周期 CPU

一条指令在一个时钟周期内完成：取指、译码、执行、访存、写回都在同一拍里发生。周期必须长到能覆盖最慢的那条路径（通常是 `lw`：取指加数据存储器）。

### 硬件部件

- `PC`：程序计数器，保存当前指令地址。
- `Memory`：主存。单周期里常把指令存储器和数据存储器画成两块，避免同一拍既取指又访存。
- `Register File`：寄存器堆。需要两个读口（`rs1`、`rs2`）和一个写口（`rd`）。`x0` 恒为 0。
- `ALU`：算术逻辑单元，完成加减、比较、逻辑和移位。
- `Mux`：多路选择器，按控制信号在若干来源里挑一个，例如 ALU 的第二操作数是寄存器还是立即数。

### 控制信号

- `PCSrc`：下一拍 PC 来自 `PC+4`、分支目标还是跳转目标。
- `RegWrite`：是否把结果写入寄存器堆。
- `MemWrite`：是否写入数据存储器（`sw`/`sh`/`sb`）。
- `MemToReg`：写回寄存器的数据来自 ALU 还是来自存储器。
- `MemRead`：是否读数据存储器（`lw`/`lh`/`lb` 等）。
- `ALUSrc`：ALU 的第二输入来自 `rs2` 还是立即数。
- `ALUOp`：ALU 做哪一种运算，通常再结合 `funct3`/`funct7` 细译。
- `Branch`：本指令是条件分支。
- `Jump`：本指令是无条件跳转（`jal`/`jalr`）。

组合逻辑根据 `opcode` 拉高这些信号。单周期没有流水线寄存器，也就没有“上一拍的控制还留在通路里”的问题。

## 流水线 CPU

把执行拆成彼此重叠的阶段，让不同指令同时占用不同硬件。理想情况下时钟可以按最慢那一级来定，吞吐接近每拍一条。

### 流水线阶段

- `IF`：取指。用 PC 读指令存储器，并计算 `PC+4`。
- `ID`：译码。读寄存器堆，符号扩展立即数，产生控制信号。
- `EX`：执行。ALU 运算，或计算访存有效地址、分支目标。
- `MEM`：访存。仅 load/store 真正使用数据存储器；其他指令空过这一级。
- `WB`：写回。把 ALU 结果或读出的数据写入 `rd`。

### 流水线寄存器

相邻两级之间插入寄存器，把本拍算完的数据和控制一起交给下一拍。这样当指令 B 进入 `ID` 时，指令 A 的操作数已经锁在 `ID/EX` 里，不会被 B 的译码覆盖。

- `IF/ID`
- `ID/EX`
- `EX/MEM`
- `MEM/WB`

控制信号也随指令向前流动，避免后进入的指令改掉前一条还在用的 `RegWrite`、`MemWrite` 等。

## 冒险与处理

### 数据冒险

后面的指令要读的寄存器，前面的指令还没写回。源寄存器是 `rs1` 或 `rs2`，目的寄存器是 `rd`。

普通数据相关：`addi` 的结果要到 `WB` 才进寄存器堆，紧接着的指令在 `ID` 就已经读寄存器，读到的是旧值。

```asm
addi x1, x1, 1
addi x2, x1, 2
addi x3, x1, 3
```

load-use 相关更紧：`lw` 的数据要到 `MEM` 结束才就绪，下一条若在 `EX` 就要用这个值，转发也来不及，必须停顿一拍。

```asm
lw x1, 0(x2)
addi x3, x1, 1
```

**停顿：** 把后续指令的控制信号清零（变成空操作），并冻结 PC 与 `IF/ID`，让后一条指令多等一拍。相邻 ALU 相关若只靠停顿，往往要等两拍才能从寄存器堆读到新值。

**转发（旁路）：** ALU 结果在 `EX` 结束时已经出现在 `EX/MEM` 里，不必等到 `WB`。

- 相邻指令：下一条在 `ID`/`EX` 需要这个值时，从 `EX/MEM` 直接接到 ALU 输入。
- 隔一条的指令：结果可能已经走到 `MEM/WB`，从那里转发到更早的阶段。

实现上要有转发单元，比较后一条的 `rs1`/`rs2` 与前两条的 `rd`，并确认前一条确实会写寄存器。硬件上就是从 `EX/MEM`、`MEM/WB` 拉回 ALU 输入端的旁路线。load-use 仍然必须停顿：数据在 `MEM` 才出现，无法从 `EX` 转出。

### 控制冒险

分支是否跳转、目标地址是什么，要到 `EX` 才算完，而下一拍 `IF` 已经取了顺序下一条。取错就要作废。

**分支预测：**

- 静态预测：最简单是始终预测不跳转，按 `PC+4` 取指；预测失败再冲刷。
- 动态预测：用分支历史表记住最近几次跳没跳，准确率通常更高。

**尽早判断：** 比较器和目标地址计算可以前移到 `ID`。再配合转发，误预测时冲刷的级数至少能少一拍。`jal` 的目标在译码后就能确定；`beq` 还要等操作数就绪。

冲刷的做法是把已取错的指令对应的流水线寄存器控制位置零，并改写 PC。

### 结构冒险

同一拍有两个阶段要抢同一硬件。最典型的是单一存储器既要给 `IF` 取指，又要给 `MEM` 做 load/store。

解决办法是把指令存储器和数据存储器分开（或用分离的 I-Cache / D-Cache）。寄存器堆则做成“先写后读”或带内部转发，让 `WB` 和 `ID` 可以同一拍访问。

## 异常与中断

异常是指令执行过程中的意外，例如非法指令、对齐错误；中断来自外部请求。两者都要求 CPU 立刻离开当前指令流。

处理过程：

1. 把当前 PC（或下一条 PC）写入异常程序计数器一类的寄存器，以便返回。
2. 保存需要恢复的通用寄存器和状态寄存器。
3. 根据原因跳到对应的陷阱处理程序。

流水线里还要作废异常指令之后已经取进来的指令，并阻止它改写存储器或寄存器。精确异常要求：异常点之前的指令都完成，之后的都像没执行过。

Cache 和页表处理的是访存延迟与地址翻译，数据通路本身仍按本节的阶段推进。

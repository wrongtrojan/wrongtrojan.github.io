CPU 跑得比主存快得多，若每条 load/store 都等到 DRAM，流水线前面谈的转发与停顿都填不平这个缺口。Cache 把最近用过的块放在更小更快的 SRAM 里，靠程序的局部性把平均访存时间拉下来。

## 局部性与层次

时间局部性是刚访问过的位置很快还会再被访问，循环里的计数器、累加器都是。空间局部性是邻近地址也容易被碰到，顺序扫数组就是。层次从寄存器到 L1/L2/L3 再到主存、磁盘，越往下容量越大、延迟越高。一次访存从最内层找起，未命中再向外走。

## 行、组与路

Cache 以块（行）为传输单位，一块通常 32 或 64 字节。主存地址被切成三截：标记、组索引、块内偏移。偏移在行内选字节；组索引选出唯一一组；标记用来确认这一行是不是想要的块。

直接映射让每个块只能进一个组、每组一行，硬件简单，冲突却多：两个经常交替使用的块若映射到同一组，会把彼此挤出去。全相联相反，任何块都可以进任何行，比较电路的开销昂贵。$n$ 路组相联是折中：一组里放 $n$ 行，块先按索引进组，再在组内找空行或替换。

## 命中、缺失与写

地址的组索引命中且标记相符，就是命中，再按偏移取出数据。否则就是缺失：向下一层取整块填进来，再完成这次访问。冷缺失是第一次碰到该块；冲突缺失来自组太窄，不同块把彼此挤出去；容量缺失则是工作集比 Cache 还大。

写命中有两种脾气。写直达同时更新 Cache 与下一层，简单但总线忙；写回只改 Cache 并打脏位，行被替换时才写回，省带宽。写缺失可以写分配（先把块读进来再写）或不写分配（直接写下一层）。替换常用 LRU 或近似 LRU，随机替换也有人用。

## 直接映射算一遍

设 Cache 容量 $C=64$ 字节，块大小 $B=8$ 字节，于是共 $C/B=8$ 行，直接映射下就是 8 组。字节地址 $a$ 的偏移是 $a \bmod 8$，组号是 $\lfloor a/8 \rfloor \bmod 8$，标记是 $\lfloor a/64 \rfloor$。地址 0 与 64 组号相同、标记不同，会争同一行，这就是冲突缺失的典型样子。组相联把这 8 行收成更少的组、每组多路，冲突会减轻，查找要在组内比较多个标记。

Cache 通常看到的是物理地址，或虚实混合索引。缺页发生在翻译失败之后，和这里的缺失不是同一件事，但都会变成一次很慢的访存。

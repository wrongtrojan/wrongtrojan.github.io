递归是把原问题交还给同一套规则、只把规模变小的写法。能写对，靠的是下面几条法则；写出来之后，再用汉诺塔、迷宫和找零把法则落到具体步骤上。

## 基本法则

基准情形要求：有某些情形不需要递归就能直接求解，否则调用永远停不下来。不断推进要求每一次递归调用都朝着产生基准情形的方向走，问题规模必须真正变小。设计法则允许先假设所有递归调用都能运行，不必事先把簿记管理的细节想清楚。合成效益法则禁止对同一个问题实例在不同递归调用里做重复性工作——同一子问题算过一次就该记住。

## 书写方式（准确性待商榷）

动手写时先确定递归的基准情形，也就是递推的尽头和回归的开始；再把问题分解为低一规模问题，找到演进方式；然后假设函数已经能实现低一规模问题，用这次调用去解决高规模问题。下面的阶乘就是这条路：`n <= 1` 直接返回 1，否则乘上 `fact(n - 1)`。

## 复杂的递归问题

汉诺塔把三根柱子记成起点、中间和终点。要移动高度为 `height` 的一叠盘子，先借助终点柱，把高度为 `height-1` 的一叠移到中间柱子；再把最底下那一个盘子移到终点柱子；最后借助起点柱子，把高度为 `height-1` 的一叠从中间柱子移到终点柱子。`n == 0` 就是基准情形。

探索迷宫用的是 DFS（深度优先）。从起始位置开始，首先向北移动一格，在新位置递归重复；若向北行不通，尝试向南移动一格再递归；向南也行不通，就尝试向西；北、南、西都不行，再尝试向东。四个方向都不行，意味没有出路。为避免陷入循环，已经探索过的位置不再探索。迷宫式搜索的框架见[深度优先算法](/note/computerscience/dsaa/深度优先算法/)。

找零可以先用贪婪算法，尽可能用面值大的硬币，但面值不标准时不一定最优。改成递归时，基准情形是找的零钱金额与某一枚硬币面值相同，只需要 1 枚硬币；不断推进则是减去 1 枚硬币后比较大小再选择。基础递归有大量重复性计算，直接违背合成效益法则，所以要把已经算过的找零数目储存起来，在递归中查询，这就是记忆化。动态规划则从 1 分找零开始，系统地计算到所需的找零金额，是一种有比较的递推算法；带比较的递推见[动态规划](/note/computerscience/dsaa/动态规划/)。

```cpp
#include <iostream>

void hanoi(int n, char from, char via, char to) {
    if (n == 0) return;
    hanoi(n - 1, from, to, via);
    std::cout << from << " -> " << to << '\n';
    hanoi(n - 1, via, from, to);
}

long long fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

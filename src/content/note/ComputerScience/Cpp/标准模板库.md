泛型程序设计并不绑死在某一种数据类型上。C++ 里主要靠模板：类型作为参数走进模板，只要它提供算法所要求的那一组操作。这组操作叫概念（concept），满足它的类型是这个概念的一个模型（model）。若概念 A 所要求的功能也是概念 B 所要求的，则 B 是 A 的子概念。

STL 把容器、迭代器、函数对象和算法拆开。容器用来容纳一组元素；迭代器按顺序访问这些元素，算法只通过迭代器说话；函数对象可以像函数一样被调用；算法本身是函数模板，覆盖查找、排序、消除、计数、比较、变换、置换和容器管理，七十多种。容器库有十三种：`vector`、`deque`、`list`、`forward_list`、`array`、`set`、`multiset`、`map`、`multimap`，以及后四种的无序形式 `unordered_set`、`unordered_multiset`、`unordered_map`、`unordered_multimap`。顺序容器是向量、双端队列、列表、单向链表和数组；关联容器是集合与映射，有序的按键排列，无序的用哈希组织。独立于容器的迭代器要包含 `<iterator>`，标准函数对象在 `<functional>`，算法在 `<algorithm>`。

## 迭代器

每个容器类模板都定义一组对应的迭代器。算法通过迭代器访问指定位置，不必知道元素的具体类型。指针本身就是一种迭代器，迭代器是泛化的指针。通用操作是前置 `++p`（指向下一元素并返回自身引用）和后置 `p++`（指向下一元素，返回类型不确定）。算法操作的是半开区间 `[first, last)`：`first` 指向第一个元素，`last` 指向末元素的下一位置。

按能力分成五类。输入迭代器（Input Iterator）从序列读取数据，不一定能写；输入源单向消耗，适合只遍历一次的算法。它支持 `p1 == p2`、`p1 != p2`、用 `*p1` 取值、`p1->m` 等价于 `(*p1).m`，以及 `*p++`（先取出再前进）。输出迭代器（Output Iterator）向序列写入，不一定能读；`*p1 = t` 写入一个元素，`*p1++ = t` 等价于先赋值再自增；写入与自增必须交替进行。前向迭代器（Forward Iterator）可读可写，支持对序列做可重复的单向遍历，并保证 `*p1` 具有 `T &` 类型、后置 `++` 使迭代器指向下一元素。双向迭代器（Bidirectional Iterator）在前向基础上增加反向移动：`--p1` 指向上一元素并返回自身引用，`p1--` 同样后退。随机访问迭代器（Random Access Iterator）再把迭代器一次移动 n 个位置：`p1 += n`、`p1 -= n`，`p1 + n` 与 `n + p1` 得到前 n 个元素处的迭代器，`p1 - n` 得到后 n 个处的，`p1 - p2` 返回满足 `p1 == p2 + n` 的整数 n，还可用大小关系比较指向位置的前后，`p1[n]` 等价于 `*(p1 + n)`。内置指针是随机访问迭代器。

流迭代器让 iostream 直接参与算法，本身是适配器：适配器一般不提供新功能，只改对象接口。输入流迭代器 `istream_iterator<T>` 从输入流连续读入类型 `T` 的数据，`T` 要有默认构造且能用 `>>` 提取。用 `istream_iterator<T>(istream &in)` 构造实例；默认构造出来的迭代器表示流的结束位置，拿它与当前迭代器比较即可判断是否读完。输出流迭代器 `ostream_iterator<T>` 要求 `T` 能用 `<<` 插入。构造可以是 `ostream_iterator(ostream &out)`，也可以带分隔符 `ostream_iterator(ostream &out, const char *delimiter)`。对 `*iter` 赋值相当于执行 `out << x`（若有分隔符再输出 delimiter）；它的 `++` 不改变迭代器状态，只是为了统一接口。

辅助函数模板 `advance` 让迭代器按自身能力前进或后退多个元素，`distance` 计算两个迭代器之间的距离。

下面这个短例子把向量、随机访问迭代器、`sort` 和输出流迭代器串在一起：

```cpp
#include <algorithm>
#include <iostream>
#include <iterator>
#include <vector>

int main() {
    std::vector<int> v{3, 1, 4, 1, 5};
    std::sort(v.begin(), v.end());
    std::copy(v.begin(), v.end(), std::ostream_iterator<int>(std::cout, " "));
}
```

## 容器

所有容器都有默认构造 `S s1`，得到空容器；关系运算符按字典序比较元素；`begin` 返回指向第一个元素的迭代器，`end` 返回末元素下一位置；`clear` 清空，`empty` 判断是否为空，`size` 给出元素个数，`swap` 与另一容器交换内容。标准容器至少是可逆容器，因而还有逆向迭代器：`rbegin` 指向最后一个元素，`rend` 指向第一个元素的前一位置。类型名是 `S::reverse_iterator` 与只能读不能写的 `S::const_reverse_iterator`。逆向迭代器是普通迭代器的适配器，二者可以互相转换：若 `p1` 是 `S::iterator`，则 `S::reverse_iterator(p1)` 得到对应的逆向迭代器。

### 顺序容器

顺序容器可以用给定元素或已有迭代器区间构造：`S s(n, t)` 放 n 个 t，`S s(n)` 放 n 个默认构造的 `T()`，`S s(q1, q2)` 用半开区间 `[q1, q2)` 里的数据填充。成员 `assign` 会先清掉原有元素再赋值，形式同样是 `assign(n, t)`、`assign(n)`、`assign(q1, q2)`。插入必须用指向当前容器的迭代器标明位置：`insert(p1, t)` 在 `p1` 之前插入并返回指向新元素的迭代器，`insert(p1, n, t)` 插入 n 个 t 且无返回值，`insert(p1, q1, q2)` 把 `[q1, q2)` 顺序插到 `p1` 之前，`emplace(p1, args)` 用 args 就地构造后插入并返回新元素迭代器。删除用 `erase(p1)` 去掉一个元素并返回下一位置，`erase(p1, p2)` 去掉 `[p1, p2)` 并返回最后被删元素的下一位置。`resize(n)` 把大小改成 n，多余的删掉，不够的用 `T()` 补。`front` 与 `back` 给出首尾元素的引用。尾部有 `push_back(t)`、`emplace_back(args)`、`pop_back()`；头部有 `push_front(t)`、`emplace_front(args)`、`pop_front()`。也可用列表初始化。

向量支持高效随机访问和尾部增减，中部或头部插入删除要移动元素。空间不够时动态扩容并预留额外容量。特有操作是 `capacity` 查看已分配容量，`reserve(n)` 预留至少 n 的容量，`shrink_to_fit` 收回未使用空间。扩容会使全部迭代器、指针和引用失效；未扩容的插入或删除只让插入/删除位置之后的迭代器、指针和引用失效。

双端队列两端插入删除高效且不必移动元素，随机访问慢于向量，中间插入删除仍要移动。两端操作会使所有迭代器失效，但指针和引用仍有效；中间操作则迭代器、指针和引用全部失效。

列表不支持随机访问，任意位置插入删除只改指针、不必移动元素，并支持 `splice` 把另一个 `list` 的元素高效转移过来，以及 `remove` 按值删除指定元素。失效范围很小：只有被删除元素自己的迭代器、指针和引用失效。

单向链表只能向前遍历，插入删除用 `insert_after` 与 `erase_after`，没有 `size()`。数组 `array` 是内置数组的封装，大小固定，支持随机访问，更安全但不能动态扩容。

按访问模式选：大量随机访问加尾部操作用向量，两端操作加少量随机访问用双端队列，中部频繁插入删除用列表或单向链表，固定大小用数组。

除 `array` 外，还可以通过插入迭代器往顺序容器里写：`front_insert_iterator`、`back_insert_iterator` 和 `insert_iterator` 三个类模板。顺序容器适配器再封装一层，按指定顺序访问和删除元素，常见的是栈 `stack`、队列 `queue` 和优先队列 `priority_queue`。

### 关联容器与无序容器

关联容器里元素按键升序排列，最大优势是按键高效查找。按是否允许重复键分成单重（键唯一：集合与映射）和多重（允许重复：多重集合与多重映射）；按键与元素的关系分成简单关联（元素本身就是键：集合与多重集合，只有一个类型参数）和二元关联（元素由键加附加数据构成：映射与多重映射，有两个类型参数）。键必须能用 `<` 比较；若键是类类型就要重载该运算符，并且 `<` 必须构成严格弱序：非自反（`x < x` 为假），传递（`x < y` 且 `y < z` 则 `x < z`），以及由 `!(x < y) && !(y < x)` 定义的等价关系也要传递。

构造可用迭代器区间 `S s(q1, q2)`。单重容器遇到相同键只收第一个，多重容器无条件全收。插入不必用迭代器指定位置：`insert(t)` 在单重容器成功时返回 true、失败则返回同键元素的迭代器和 false，在多重容器返回已插入元素的迭代器；`insert(p1, t)` 把 `p1` 当作位置提示且总返回一个迭代器；`insert(q1, q2)` 对区间内每个元素依次 `insert`。删除除了 `erase(p1)` 与 `erase(p1, p2)`，还允许按键 `erase(k)`。基于键的查找和计数是 `find(k)`（找到任一键为 k 的元素否则返回 `end`）、`lower_bound(k)`（第一个键不小于 k）、`upper_bound(k)`（第一个键大于 k）、`equal_range(k)`（刚好覆盖所有键为 k 的半开区间）和 `count(k)`（键为 k 的个数）。列表初始化时，一元关联容器直接给元素列表，二元关联容器给键值对。

集合的元素个数必须有限。映射类似字典，支持 `[]`：可以用它插入新元素、修改或查询已有元素的附加数据。多重集合允许重复键。多重映射同样允许重复键，但不支持 `[]`。

无序容器用哈希函数和键类型的 `==` 组织元素。键没有明显序关系、或维护顺序代价很高时，无序容器更合适。默认用 `hash<key_type>` 生成哈希值；自定义类型要自己提供 `hash` 模板。

## 函数对象与算法

函数对象是行为类似函数的对象，可以无参或带若干参数，用来取值或改变操作对象。普通函数、函数指针、lambda 和重载了 `()` 的类对象都可以当函数对象用。常用的分成五类：产生器（Generator）零个参数，一元函数（Unary Function）一个参数，二元函数（Binary Function）两个参数，以及返回 `bool` 的一元谓词（Unary Predicate）和二元谓词（Binary Predicate）。标准库里的二元函数对象有 `plus<T>`、`minus<T>`、`multiplies<T>`、`divides<T>`、`modulus<T>` 和一元的 `negate<T>`；谓词有 `equal_to<T>`、`not_equal_to<T>`、`greater<T>`、`less<T>`、`greater_equal<T>`、`less_equal<T>`，以及逻辑上的 `logical_and<T>`、`logical_or<T>`、`logical_not<T>`。

lambda 像未命名的内联函数，可以写在函数内部，形如 `[捕获列表](参数列表) -> 返回类型 { 函数体 }`，返回类型可省，采用尾置返回；捕获列表列出所在函数里要用的局部变量。参数绑定 `bind` 把一种函数对象转成另一种符合要求的：`bind(F &&f, Args &&... args)`，用法如 `auto newFunc = bind(Func, arg_list)`，把已有可调用对象的若干实参绑死。

算法本身是函数模板。不可变序列算法不直接改容器内容，做查找、相等检查和对元素计数：查找位置并返回结果，查找某个元素并返回元素或其值，或者只判断它是否在容器里。可变序列算法会改写元素，包括复制 `copy`、生成 `generate`、删除 `remove`、替换 `replace`、倒序 `reverse`、旋转 `rotate`、交换 `swap`、变换 `transform`、分割 `partition`、去重 `unique`、填充 `fill` 和洗牌 `shuffle`。

排序和搜索算法按组是：四个排序 `sort`、`partial_sort`、`partial_sort_copy`、`stable_sort`；四个二分查找 `binary_search`、`lower_bound`、`upper_bound`、`equal_range`；两个合并有序区间 `merge`、`inplace_merge`；四个最值 `min`、`max`、`min_element`、`max_element`；三个排列相关 `lexicographical_compare`、`next_permutation`、`prev_permutation`；五个有序集合运算 `includes`、`set_union`、`set_intersection`、`set_difference`、`set_symmetric_difference`；四个堆操作 `make_heap`、`pop_heap`、`push_heap`、`sort_heap`。数值算法要包含 `<numeric>`，典型的是累加 `accumulate`、内积 `inner_product`、部分和 `partial_sum` 与相邻差 `adjacent_difference`。算法通过迭代器说话，同一套 `sort` 可以作用在数组、`vector` 或自己写的容器上。

## 流类库与输入输出

流是一种抽象，在数据生产者和消费者之间建立联系并管理流动。程序把流对象看作文件对象的化身。读叫提取，写叫插入。

### 输出流

最重要的三个输出类是 `ostream`、`ofstream` 和 `ostringstream`。`cout` 是标准输出；`cerr` 是标准错误且无缓冲，内容立即写出；`clog` 类似 `cerr` 但有缓冲，缓冲区满才输出。命令行 `> filename` 会把 `cout` 重定向到文件，屏幕上看不到，`cerr` 不受 `>` 影响仍显示在屏幕上，要用 `2> filename` 才能重定向。

`ofstream` 支持磁盘文件输出。可在打开前或打开后指定二进制或文本模式；`ios` 与 `ostream` 的格式化和成员函数都能用。在构造函数里给出文件名则构造时自动打开，也可以先默认构造再 `open`，或在已打开的文件标识符上构造。预定义的 `cout`、`cerr`、`clog` 不必再构造。文件流可以先 `ofstream myFile;` 再 `myFile.open("filename")`，或直接 `ofstream myFile("filename")`。同一个流对象可以先后打开不同文件，但同一时刻只打开一个。

插入运算符 `<<` 为所有标准类型预先设计，与操纵符一起控制格式。许多操纵符定义在 `ios_base` 和头文件 `<iomanip>` 中。输出宽度用 `setw` 或成员 `width` 指定；默认填充符是空格，用 `fill` 改填充字符。`setw` 和 `width` 都不截断，数值超出指定宽度时仍显示全部，并且只影响紧随其后的那一个域，输出完宽度恢复默认。

输出默认右对齐。带参数的 `setiosflags`（定义在 `<iomanip>`）设置对齐，影响持续到用 `resetiosflags` 恢复为止。参数是格式标志，可用 `|` 组合：`ios_base::skipws` 在输入中跳过空白，`left` 左对齐并用填充字符填右边，`right` 右对齐填左边，`internal` 在规定宽度内于前缀符号之后、数值之前插入填充字符，`unitbuf` 每次插入后转储并清除缓冲区。

精度相关标志有 `showpoint`（浮点显示小数点和尾部 0）、`showpos`（非负数显示正号）、`scientific`（科学格式）、`fixed`（定点格式，无指数部分）。可用 `setprecision` 配合 `fixed` 与 `scientific`：未指定后两者时精度表示有效数字位数；设置了 `fixed` 或 `scientific` 后精度表示小数点后位数。

进制方面，`showbase` 插入前缀表明整数数制，`uppercase` 让十六进制显示 A–F、科学格式显示 E，`dec`、`oct`、`hex` 分别以十、八、十六进制格式化，并且这三个操纵符同时设定输入和输出的缺省进制。

输出流成员函数分成三类：与操纵符等价的、执行非格式化写的、以及其他修改流状态的。顺序的格式化输出可以只用插入运算符和操纵符；随机访问的二进制磁盘输出则要靠其他成员函数，插入运算符可选用。打开文件时在构造函数或 `open` 里把流与磁盘文件关联，并可以指定 `open_mode`：`ios_base::app` 打开输出文件并在尾部添加，`ate` 打开现存文件并定位到结尾，`in` 打开输入文件只读不写，`out` 打开文件输出（对 `ofstream` 隐含指定），`trunc` 打开并删除原有内容（若没有指定非 `out` 则为隐含），`binary` 以二进制模式打开（默认是文本）。`close` 关闭关联的磁盘文件，用完必须关闭以完成所有磁盘输出；要在同一流对象上打开另一文件也得先 `close`。若析构前没调用 `close`，析构函数会自动关闭。

`put` 把一个字符写到输出流，不受格式化参量影响。`write` 把内存一块内容写入文件输出流，长度参数给出字节数，遇到空字符也不停止，因而能写入完整的类结构；两个参数是 `char` 指针（需 `reinterpret_cast` 显式转换）和字节数。文件输出流保存内部指针指出下一次写的位置：`seekp` 设置该指针以便随机写盘，`tellp` 返回位置指针的值。

错误处理上，`bad` 在出现不可恢复错误时返回非 0；`fail` 在不可恢复错误或预期条件不满足时返回非 0，无参调用 `clear` 可清除错误标记；`good` 在所有错误标记和文件结束标记都清除时返回非 0；`eof` 遇到文件结尾返回非 0；`clear` 设置内部错误状态，默认参数则清除所有错误位；`rdstate` 返回当前错误状态。`!` 运算符重载后与 `fail` 相同；`void*()` 也经过重载，效果与 `!` 相反，但不等价于 `good`，因为它不检测文件结尾。

不同操作系统的文本行分隔符不同。Windows 文本文件用换行加回车作为行分隔，因而以文本模式输出时，写出的换行符会被自动扩充一个回车符。若这造成问题，就要在打开模式里加上 `ios_base::binary`，所写字符不再转换。

字符串输出流 `ostringstream` 用来生成字符串，是 `ostream` 的派生类，具备 `ofstream` 的大部分功能，但没有专用于文件的 `open` 和 `close`。两个构造函数：一个形参表示打开模式；另一个接收两个形参，先给流赋初值再指定打开模式。特有成员 `str` 返回表示流中内容的 `string`。`to_string` 函数模板能把任何支持 `<<` 的类型转成字符串。

### 输入流与双向流

输入流是数据流出的源头，最重要的是 `istream`、`ifstream` 和 `istringstream`。`istream` 适合顺序文本输入，包含基类 `ios` 的全部功能。预定义对象 `cin` 从标准输入设备读取；命令行 `<` 可以把标准输入重定向到文件。`ifstream` 支持磁盘文件输入，可指定二进制或文本模式；构造时给文件名则自动打开，否则默认构造后再 `open`。文件输入可以 `ifstream myFile;` 再 `open("filename")`，也可以 `ifstream myFile("filename")`，或先把名字放进 `string` 再交给构造函数。

提取运算符 `>>` 对所有标准类型预先设计，用于格式化文本输入，以空白符为分隔。若文本本身含空白，就要用非格式化的 `getline`。输出流那套错误处理函数同样适用于输入流。定义在 `ios_base` 和 `<iomanip>` 里的操纵符也能用于输入，真正有实际影响的主要是 `dec`、`oct`、`hex`；`hex` 接受多种书写，遇到 0–9、A–F、a–f 和 X 以外的字符就终止数值转换。

打开输入文件通常指定 `ios_base::in`（默认，用于输入）和可选的 `binary`。同一流对象打开另一文件前要先 `close`。`get` 是非格式化读取，功能与 `>>` 相仿但会读入空白字符。`getline` 可从流中读多个字符并指定终止字符（默认换行）：成员 `getline` 读完后删除终止字符，内容放进不能扩容的字符数组；非成员 `getline` 声明在 `<string>` 中，把内容保存在 `string` 里更方便，可接受输入流、目标 `string` 和可选的终止字符三个参数。`read` 从文件读字节到指定内存，由长度参数决定要读的字节数，遇到文件结束或文本模式中的结束标记就停止。文件输入流保留指向下一读位置的内部指针，用 `seekg` 设置，`tellg` 返回当前读指针，类型是 `streampos`。

`istringstream` 提供与字符串输出流对应的功能。最常用的构造函数接受要解析的 `string` 和打开模式（默认 `ios_base::in`）。它有 `ifstream` 的大部分能力，只是没有 `open` 和 `close`。

一个 `iostream` 对象既可以是数据源也可以是目的。`fstream` 和 `stringstream` 都从 `iostream` 派生，同时继承 `istream` 与 `ostream`。`fstream` 支持磁盘文件的输入和输出，一般是带两个逻辑子流的单个流；`stringstream` 面向字符串，可对同一个字符串交替读写。

宽字符、宽字符串用来处理汉字占两个 `char` 时的问题。宽字符类型是 `wchar_t`，通常占两字节；宽字符字面量仍用单引号，但第一个单引号前加 `L`。`wstring` 是宽字符串，除元素是 `wchar_t` 外与 `string` 相同，字面量用双引号并在第一个双引号前加 `L`。`wstring` 不能用 `cout` 输出，因为 `cout` 的基本单位是 `char`。在输入、输出和输入输出流的名字前加 `w` 就得到对应的宽流，例如 `wcout`。

把对象写入文件的过程叫串行化（序列化）。串行化后的对象可以通过网络传给其他计算机，或存进数据库。

## 异常处理

环境条件意外或用户操作不当时，要有合理的处理办法。运行中可预料但不可避免的错误，应给出适当提示。C++ 异常机制让异常的引发和处理不必写在同一个函数里。

`throw` 表达式抛出对象，语法与 `return` 相似，操作数标识异常类型。`try` 后面的复合语句是保护段，即预料可能发生异常的代码；一个 `try` 后面可以跟多个 `catch`。`catch` 后面的复合语句是异常处理程序，捕获 `throw` 抛出的异常；其中可以用 `throw;` 把当前异常对象再次抛出。`catch` 的异常声明指明处理的类型和参数名，写法类似函数形参。匹配规则是：`catch` 的类型就是抛出对象的类型或引用；或者是抛出对象的公有基类或对该基类的引用；或者抛出的是指针且可隐式转换成 `catch` 所声明的指针类型。

旧式动态异常规格写在函数声明里，列出该函数可能抛出的类型，例如 `void fun() throw(A, B, C, D)`。声明中没有异常接口则可以抛任何类型；`void fun() throw()` 表示不抛任何异常。若函数抛出了接口声明不允许的异常，会调用 `unexpected`，其缺省行为是再调用 `terminate` 终止程序。这种规格已经过时。

从进入 `try` 到异常抛出之前，栈上构造的局部对象会按析构顺序自动析构，称为栈解旋（stack unwinding）。

标准库异常分散在若干头文件中。`bad_alloc` 表示 `new` 动态分配失败。`bad_cast` 表示 `dynamic_cast` 失败。`bad_typeid` 出现在对空指针 `p` 做 `typeid(*p)` 时。`bad_exception` 出现在函数抛出了声明不允许的异常、`unexpected` 被调用、而 `unexpected` 又再次抛出该函数不允许的异常时。`ios_base::failure` 表示输入输出流执行过程中的错误。`<stdexcept>` 里，`runtime_error` 派生出算术向下溢出的 `underflow_error`、向上溢出的 `overflow_error`、以及内部计算发生作用域错误的 `range_error`；`logic_error` 派生出参数不在允许范围的 `out_of_range`、试图创建超过最大允许长度之对象的 `length_error`、传入无效参数的 `invalid_argument`、以及程序先决条件不满足的 `domain_error`。`runtime_error`、`logic_error` 及其派生类都有接受 `const string &` 错误信息的构造函数，调用 `what` 可以得到构造时写入的那条信息。文件流也可以设为失败时抛 `ios_base::failure`。

现代写法用 `noexcept` 说明符标识函数不会抛异常，形如 `type func() noexcept;`，声明与定义必须一致。若标了 `noexcept` 却仍抛出，执行时仍可能直接终止。`noexcept` 说明符与 `noexcept` 运算符配套：运算符判断某个表达式是否承诺不抛异常。

分配失败时可以这样捕获：

```cpp
try {
    auto *p = new int[n];
    delete[] p;
} catch (const std::bad_alloc &) {
    // 分配失败
}
```

## 易错点

`vector` 扩容后全部迭代器失效，未扩容的插入删除也会让该位置之后的迭代器失效；不能在循环里保存旧的 `end()`，也不能在扩容之后继续使用扩容前拿到的迭代器。`map[k]` 在键不存在时会插入默认值，只查询应当用 `find`。析构函数里抛异常会在栈解旋过程中再次引发异常，程序直接调用 `terminate`；异常规格写错（包括旧式 `throw()` 与 `noexcept` 不一致）同样可能终止。流的 `>>` 失败默认只置状态位、并不抛异常，必须检查 `fail`/`good` 或打开异常掩码后才会变成 `ios_base::failure`。

## 基类与派生类

派生类从基类得到已有的成员。只有一个直接基类时称为单继承，有多个直接基类时称为多继承；基类的基类叫做间接基类。已有的类称为基类或父类，新类称为派生类或子类。

派生类的定义语法是：

`class 派生类名 : 继承方式 基类名列表 { 派生类成员声明; };`

一个派生类可以有多个基类，称为多继承；也可以只有一个直接基类，称为单继承。类族中直接派生出某类的基类称为直接基类；基类的基类，或更高层的基类，称为间接基类。

继承方式规定了如何访问从基类继承来的成员。对 `class` 而言，系统默认的继承方式是私有继承。派生类成员是指除了从基类继承来的成员之外、新增加的数据成员和函数成员。

## 派生类的生成过程

派生一个新类，要依次做三件事：吸收基类成员、改造基类成员、添加新的成员。

### 吸收基类成员

派生类会吸收基类的数据成员和函数成员，但不包含基类的构造函数和析构函数。构造与析构要在派生类里另行声明，以便完成派生类自己的初始化和扫尾。

### 改造基类成员

改造首先是基类成员的访问控制问题，主要依靠派生类定义时写下的继承方式来控制：公有继承、私有继承或保护继承会把基类成员变成派生类里不同的访问属性，下一节用表列出。

改造的另一面是基类成员的覆盖或隐藏。覆盖是虚函数在派生类里改写基类版本，由动态绑定决定调用哪一个。隐藏则是：派生类声明了和基类同名的数据或函数，直接写这个名字拿到的是派生类版本。隐藏发生在静态绑定下，与是否声明为 `virtual` 无关。

### 添加新的成员

派生类还要加入新的、适合于本类的数据成员和函数成员。要实现特别的初始化和扫尾工作，必须加入新的构造函数和析构函数；基类的构造与析构不会自动变成派生类的构造与析构。

## 继承访问控制

派生类继承了基类除构造函数、析构函数之外的所有成员，但这些成员在派生类中的访问属性可以调整。基类的私有成员在三种继承方式下都不可直接访问。

**公有继承（`public`）**：基类的公有成员和保护成员在派生类中访问属性不变；基类的私有成员不可直接访问。

**私有继承（`private`）**：基类的公有成员和保护成员变为派生类的私有成员；基类的私有成员不可直接访问。进一步再派生时，基类的全部成员都无法被更下层直接访问，从而终止了基类功能的继续派生。

**保护继承（`protected`）**：基类的公有成员和保护成员变为派生类的保护成员；基类的私有成员不可直接访问。

三种方式对基类成员属性的对应关系如下。`class` 默认是私有继承。

| 基类成员属性 | 公有继承 | 保护继承 | 私有继承（默认） |
| :--- | :--- | :--- | :--- |
| 公有 | 公有 | 保护 | 私有 |
| 保护 | 保护 | 保护 | 私有 |
| 私有 | 不可见 | 不可见 | 不可见 |

## 类型兼容规则

公有派生类的对象可以在需要基类对象的场合替代基类对象，规则有五条。

派生类对象可以隐含转换成临时的基类对象；这要求基类具有可用的复制构造函数或移动构造函数。

派生类的对象可以初始化基类的引用。

派生类的指针可以隐含转换为基类的指针。

替代之后，派生类对象可以作为基类对象使用，但只能使用从基类继承来的成员：经基类指针或基类引用能直接点到的，是基类接口里的那些名字。

替代并不改变对象本身的身份：对象依旧是原来的派生类对象，动态类型没有变成基类。若用派生类对象去复制构造一个真正的基类对象，那是切片，下一节多态再谈。

基类指针或引用可以指向派生类对象，但在没有虚函数的情况下，经这条指针或引用只能调用从基类继承的成员，绑的仍是基类版本。

## 派生类的构造函数与析构函数

### 构造函数

构造派生类对象时，既要对基类成员（基类子对象）进行初始化，也要对新增的成员对象进行初始化。写法是在初始化列表里依次给出基类和成员：

`派生类::派生类名(参数表) : 基类名表(参数表), 新成员对象表(参数表) {}`

若对基类初始化需要调用带形参表的构造函数，派生类就必须声明自己的构造函数，以便在初始化列表里把实参传给基类。基类若只有带参构造而没有默认构造，派生类不能指望编译器自动生成一份能用的默认构造。

### 复制构造函数

派生类复制构造函数把基类部分交给基类的复制构造去完成，类型兼容规则在这里发挥作用：派生类对象可以作为基类复制构造的实参。

`派生类::派生类名(const 派生类名 &v) : 基类名(v) { ... }`

### 析构函数

派生类析构函数的声明方法，与没有继承关系的类中析构函数完全相同：`~派生类名()`，无参数、无返回类型。析构顺序与构造相反。构造函数不能是虚函数；析构函数一般应声明为虚函数，以免经基类指针删除派生类对象时只析构基类部分。

### 被删除的基类构造函数

在基类中用 `= delete` 删除的构造函数，在派生类中也对应处于删除状态。编译器无法执行派生类中基类部分所对应的构造或赋值操作，因此派生类不能隐式获得那一份被删掉的构造或赋值。

## 派生类成员的标识与访问

按访问属性，派生类里能谈到的成员可分为：不可访问成员、私有成员、保护成员、公有成员。不可访问成员典型地来自基类私有成员，或私有继承后再往下派生时被挡住的那些名字。访问时要同时解决唯一标识问题和可见性问题：先确定名字能唯一标识哪一个成员，再确认该成员在当前作用域可见。

### 作用域分辨符 `::`

可见性原则仍然是：外层声明的标识符如果在内层没有同名标识符则可见；若内层声明了同名标识符，外层的那一个在内层不可见。

隐藏规则处理同名成员。派生类若声明了与基类同名的成员，会隐藏基类的同名成员，直接写这个名字访问到的是派生类成员。派生类若声明了与基类同名的函数，基类中该名字的全部重载都会被隐藏，并不是只藏住参数表相同的那一个；要使用基类版本，必须用 `基类名::函数名` 访问。

多继承下，若派生类的多个基类有同名成员，而派生类自己没有同名成员，必须用 `基类名::成员名` 才能唯一标识。若派生类自己也有同名成员，则它隐藏各基类的同名成员，基类成员同样要用 `基类名::成员名` 访问。

解决二义性还可以用 `using`：把基类成员引入派生类作用域，明确成员归属。`using` 也可用来让基类中同名但参数不同的函数不被隐藏，从而实现重载共存，而不是只留下派生类新写的那一个。

若多个直接基类来自同一个共同基类，沿不同路径继承过来的同名成员是不同的子对象，需要用直接基类名加上作用域分辨符才能唯一标识。若希望这些路径共享同一份子对象，就要改用虚基类。

## 虚基类

将共同基类设置为虚基类之后，从不同路径继承过来的同名成员在内存里只有一份。声明形式是：

`class 派生类名 : virtual 继承方式 基类名`

`virtual public` 与 `public virtual` 等价，都表示公有的虚继承，用来解决菱形继承里共同基类被重复包含的问题：

```cpp
class Derived : virtual public Base {};
// 等价于
class Derived : public virtual Base {};
```

### 虚基类及其派生类的构造函数

若虚基类没有默认构造函数、却有带形参的构造函数，就不能使用自动生成的默认构造函数。此时必须在派生类构造函数的初始化列表中列出对该虚基类的初始化。最派生类负责初始化虚基类子对象；中间层即使也写了对虚基类的初始化，真正构造时以最派生类给出的为准。

构造一个类对象的一般顺序是：先构造虚基类子对象，再构造直接基类子对象，再构造本类的非静态数据成员，最后执行本类构造函数的函数体。析构顺序与此相反。

## 多态的类型与绑定

多态是指同样的消息被不同类型的对象接收时导致不同的行为。

### 专用多态与通用多态

专用多态包括重载多态和强制多态。重载多态让同一运算符或同一函数名对应多份实现。强制多态把变元的类型加以变化，以符合一个函数或者一次操作的要求，例如隐式转换、强制类型转换。

通用多态包括包含多态和参数多态。包含多态是定义于不同类中的同名函数成员的多态行为，通过虚函数实现。参数多态与类模板、函数模板关联，在使用时必须赋予实际的类型才能实例化。

### 编译时多态与运行时多态

编译时的多态在编译过程中就确定了同名操作的具体操作对象。运行时的多态要到程序运行过程中才动态地确定操作所针对的具体对象。

绑定就是确定操作的具体对象，也即计算机程序中各部分彼此关联的过程：把一条信息和一个对象相结合。

静态绑定又称早期绑定或前绑定：绑定工作在编译、连接阶段完成。系统根据类型匹配等特征，确定程序中的操作与执行该操作的代码之间的关系。重载多态、强制多态和参数多态都通过静态绑定解决。

动态绑定又称晚期绑定或后绑定：绑定工作在程序运行阶段完成。包含多态通过动态绑定完成。

## 重载多态：运算符重载

运算符重载赋予已有的运算符多重含义，使同一个运算符作用于不同类型的数据时导致不同的行为。

### 运算符重载规则

只能重载 C++ 已经存在的运算符，不能发明新的运算符符号。成员访问 `.`、成员指针运算符 `.*`、作用域分辨 `::`、条件运算符 `?:`、`sizeof` 以及 `typeid` 不可重载。重载之后，运算符的优先级和结合性都不会改变。一般应使重载后的功能与原功能相近，不改变操作对象的个数，并且至少一个操作数是自定义类型。

重载有两种形式。一是非静态成员函数，形如 `返回类型 类名::operator 运算符(形参表) { 函数体 }`。此时函数参数个数比原来的操作数个数少一个（后置 `++` / `--` 除外），因为第一个操作数会作为函数调用的对象，不必出现在参数表中，由 `this` 表示。二是非成员函数，形如 `返回类型 operator 运算符(形参表) { 函数体 }`，参数个数与原操作数个数相同。

赋值 `=`、下标 `[]`、函数调用 `()`、成员访问 `->` 只能被重载为成员函数。

### 重载为成员函数

对于双目运算符 `(A类型)oprd1 操作符 (B类型)oprd2`，应当将操作符重载为 `A` 类的成员函数，形参为 `B` 类型。

对于前置单目运算 `操作符 (A类型)oprd`，应当将操作符重载为该类的成员函数，函数没有形参。前置 `++` 没有参数，通常返回引用，原型是 `Type& operator++();`：

```cpp
class Example {
    int value;
public:
    Example(int v = 0) : value(v) {}
    Example& operator++() {
        this->value++;
        return *this;
    }
};
```

对于后置单目运算符 `(A类型)oprd 操作符`，应当将操作符重载为 `A` 类的成员函数，这时函数带有一个整型形参。该整型形参不起运算作用，只用于区别前置与后置，称为哑元。后置 `++` 返回旧值的拷贝，原型是 `Type operator++(int);`：

```cpp
class Example {
    int value;
public:
    Example(int v = 0) : value(v) {}
    Example operator++(int) {
        Example temp = *this;
        this->value++;
        return temp;
    }
};
```

赋值运算要支持连续赋值 `m1 = m2 = m3`，也就是 `m1 = (m2 = m3)`，因此 `m2 = m3` 必须返回 `m2` 的引用才能继续往左边赋。参数应是对象的引用，避免不必要的拷贝，通常写成 `const M&`。函数原型一般为 `M& operator=(const M&);`。

### 重载为非成员函数

对于双目运算符 `(A类型)oprd1 操作符 (B类型)oprd2`，只需其中一个操作数是自定义类型，就可以将操作符重载为非成员函数，形参为 `oprd1` 和 `oprd2`。

对于前置单目运算符 `操作符 (A类型)oprd`，需要 `oprd` 为自定义类型，函数形参就是这个 `oprd`。

对于后置运算符 `(A类型)oprd 操作符`，需要 `oprd` 为自定义类型，形参为 `oprd` 以及一个 `int` 类型的哑元形参。

使用非成员函数重载的典型情况有两种。一是重载的操作符的第一个操作数不是可更改类型，例如左侧是标准库流对象，不能改成你的类的成员函数。二是以非成员函数形式重载，能支持更灵活的类型转换：两个操作数都出现在参数表里，转换规则对左右两侧更对称。

插入运算符 `<<` 的左端是输出流，若还要访问类的私有成员，一般声明为类的友元函数。返回值类型为 `ostream&`，以支持连续链式输出；函数参数为 `ostream&` 与类对象的常引用，避免不必要的拷贝。

## 包含多态：虚函数

虚函数必须是非静态的成员函数。需要通过基类指针指向派生类对象并访问同名成员时，在基类中将函数说明为虚函数。此时通过基类类型的指针，就可以使不同派生类的不同对象产生不同行为。

### 一般虚函数成员

声明形式是 `virtual 函数类型 函数名(形参表);`。虚函数声明只能出现在类定义中的函数原型声明上，而不能写在类外的成员函数实现处；类外定义时不再重复 `virtual`。

运行时多态需要同时满足下列条件。类之间满足赋值兼容规则（公有继承下的类型兼容）。基类中声明了虚函数。通过成员函数调用，或通过指针、引用访问该虚函数：基类指针可以指向派生类对象，基类引用可以作为派生类对象的别名；但基类对象不能表示派生类对象，不能靠一个基类值对象“装下”派生类的全部。

满足上述条件后，派生类中的虚函数便覆盖（override）基类虚函数，并隐藏基类中该名字的其他重载。在派生类里写一个与基类同名的函数时，普通函数与虚函数的差别如下：

| 函数类型 | 绑定方式 | 行为 | 使用基类指针指向派生类对象 |
| :--- | :--- | :--- | :--- |
| 普通函数 | 静态绑定 | 隐藏 | 调用时依旧使用基类版本 |
| 虚函数 | 动态绑定 | 改写（覆盖） | 调用时使用派生类版本 |

用派生类对象去复制构造基类对象，会发生对象切片：直接生成一个全新的基类对象，派生类多出来的成员被切掉，动态类型变成基类。切片之后再调用虚函数，也只能落到基类版本上。

### `override` 与 `final`

`override` 说明符表明该函数应该覆盖一个已经存在的虚函数；若实际上并未覆盖（例如签名写错），编译器报错。`final` 说明符表明该函数不能再被覆盖；若派生类试图覆盖，编译器报错。这两个说明符写在函数声明的参数列表之后，若使用了尾置返回类型，则写在尾置返回类型之后。

### 虚析构函数

C++ 中不能声明虚构造函数，但可以声明虚析构函数。目的是解决基类指针指向派生类对象时，`delete` 该基类指针无法正确析构派生类部分的问题。声明形式是 `virtual ~类名();`。

## 纯虚函数与抽象类

纯虚函数是在基类中声明的、没有定义具体操作内容的虚函数，写法是 `virtual 函数类型 函数名(参数表) = 0;`。声明为纯虚函数之后，基类中就可以不再给出函数的实现部分。

带有纯虚函数的类是抽象类。抽象类不能实例化，但可以定义指针和引用。派生类必须实现全部纯虚函数，才能定义自己的对象；只实现一部分，派生类自己仍是抽象类。抽象类给一族类型留下一套共同接口。

纯虚析构函数是例外：即使写成 `= 0`，也必须在类外提供函数体，否则链接报错，因为派生类析构时仍要调用基类析构：

```cpp
class Base {
public:
    virtual ~Base() = 0; // 声明纯虚析构函数
};
Base::~Base() {
    // 所有子类共有的清理工作
}
class Derived : public Base {
public:
    ~Derived() {
        // 先执行派生类析构函数体，结束后会调用 ~Base()
    }
};
```

## `dynamic_cast` 与 `typeid`

`dynamic_cast` 对多态类型的指针或引用进行转换：将基类的指针或引用显式转换为派生类的指针（或 `void` 指针）或引用。它与 `static_cast` 的不同在于，转换前会检查指针（或引用）所指向对象的类型与目的类型是否兼容。若不兼容，指针转换会得到空指针，引用转换会抛出异常。

`typeid` 用来获取运行时类型信息，用法是 `typeid(表达式)` 或 `typeid(类型)`。通过 `typeid` 得到的是 `type_info` 类型的常引用。`type_info` 是标准库中专门用于在运行时表示类型信息的类，该类重载了 `==` 和 `!=`，使两个 `type_info` 对象可以比较是否为同一类型。

## 函数模板与类模板

参数多态把程序所处理的对象类型参数化，使一段程序可以处理多种不同类型的对象。

### 函数模板

函数模板的定义形式是：先写 `template<模板参数表>`，再写 `类型名 函数名(参数表) { 函数体 }`。

模板参数表里可以出现三类参数。`class` 或 `typename` 加上标识符，指明可以接受一个类型参数，该类型既可以是预定义类型，也可以是自定义类型。类型说明符加上标识符，指明可以接受一个该类型的常量参数（非类型模板参数）。`template<参数表> class 标识符` 指明可以接受类模板作为参数，即模板模板参数。

模板本身不生成目标代码，由模板生成的实例才会生成目标代码。若函数模板被多个源文件引用，需要连同函数体一起放在头文件中，否则其他翻译单元看不到可实例化的定义。函数指针只能指向模板的某个实例，不能指向尚未实例化的模板本身。

### 类模板

使用类模板可以为类定义一种模式，使得类中各个数据可以取不同类型。

类内声明的形式是 `template <模板参数表>` 后接 `class 类名 { 类成员声明 };`。

类外定义成员时要重复模板头，并在类名后列出模板参数标识符：

`template<模板参数表>`

`类型名 类名<模板参数标识符列表>::函数名(参数表)`

使用形式是 `模板名<模板参数表> 对象名1, ..., 对象名n;`，例如 `Class<int> x;`。

类模板可以起别名：对尚未实例化的类模板用 `using` 起别名；对类模板的某个类实例，既可以用 `typedef`，也可以用 `using`。

类模板和函数模板都可以带默认模板实参，未写出的模板实参按默认值补齐。

## 线性群体

群体分为线性群体与非线性群体。线性群体的元素按位置排列有序，元素的次序与位置关系相对应。

线性群体有直接访问、顺序访问和索引访问三种访问方式。直接访问可以不经中间元素、直接访问群体中的任何一个元素。顺序访问只能按元素的排列顺序依次访问各个元素。索引访问则按键或下标一类的索引去定位。

直接访问群体的典型是数组类。顺序访问群体的典型是链表类。栈和队列也是线性群体，进出限制在两端。实现见[数据结构与算法](/note/computerscience/dsaa/)。

## 模板的特化与偏特化

可以为一个函数模板或类模板在某些特定参数下提供特殊的定义，这称为特化。也可以对模板类的个别成员函数和个别静态数据成员进行特化。特化之后，那一份不再是模板，而是普通的类或函数。

类模板还可以偏特化：一部分参数固定、另一部分参数仍然可变。偏特化只针对类模板。模板偏特化保留了一部分未定的参数，因此仍旧是模板。

函数模板可以像普通函数那样被重载：可以有若干个函数模板，也可以让函数模板与普通函数重载，编译器按匹配规则选择最合适的那一份。

## 模板元编程与可变参数模板

模板元编程在模板实例化的同时利用编译器完成一些计算任务，把本应在运行时计算的工作放到编译期完成。实例化过程本身就是一次编译期的“求值”，常用来做类型计算或编译期常量计算。

可变参数模板在参数类型可变的基础上，进一步实现参数个数的变化。它接受个数可变的模板参数；这些参数称为参数包，通过省略号表示零个或多个模板参数。声明语法如下，`TypeArgs` 是模板参数包，`args` 是函数参数包：

```cpp
template<typename T, typename... TypeArgs>
void func(T &t, TypeArgs &... args);
```

## 易错点

非虚函数经基类指针调用，绑的是基类版本；只有虚函数才会按对象的真实类型改写。忘记把析构写成虚函数，是经基类指针 `delete` 时资源泄漏的常见来源。同名函数隐藏会把基类全部重载一起藏住，要用 `using` 或 `基类名::` 恢复。

`=`、`[]`、`()`、`->` 必须重载为成员；`.`、`.*`、`::`、`?:`、`sizeof`、`typeid` 不能重载。前置 `++` 无参、返回引用；后置 `++` 带哑元 `int`、返回旧值拷贝。`operator=` 要返回对象引用才能链式赋值。`operator<<` 左侧是流、又要碰私有成员时，写成友元，返回 `ostream&`。

纯虚析构必须在类外给出函数体。虚继承写成 `virtual public` 或 `public virtual` 均可。模板报错信息往往很长，多半是实例化点的类型不满足模板里用到的操作，而不是模板关键字本身写错。

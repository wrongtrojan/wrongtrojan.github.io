## 标识符的作用域

作用域是标识符在程序正文中有效的区域。C++ 里常见的几类如下，彼此嵌套，但规则并不相同。

**函数原型作用域**只覆盖函数声明里的形参。声明 `void f(int n);` 时，名字 `n` 的有效范围止于这一份原型，函数体里若要用形参，必须在定义处重新写出。

**局部作用域**（也称块作用域）只在特定代码块里可见、可用。函数体、循环的花括号、条件语句的花括号都构成这样的块；块结束，其中声明的名字随之失效。

**类作用域**属于 `class` 与 `struct`。在成员函数体内，若没有声明与成员同名的局部标识符，可以直接用成员名访问该成员。在类外则必须通过三种表达式之一：对象访问 `x.m`、类访问 `X::m`，或指针访问 `ptr->m`（其中 `ptr` 是指向对象的指针）。

**限定作用域的枚举类**用 `enum class` 或 `enum struct` 声明。枚举值的访问方式与类成员相同，必须带着枚举类型名，不能泄漏到外围作用域。

**文件作用域**属于那些并不落在上述函数原型、局部、类或枚举类作用域里的声明。这样的作用域从声明点开始，一直延伸到文件末尾。命名空间里的声明、写在所有函数和类之外的变量与函数，都属于这一层。

**命名空间作用域**是给全局名字做划分的工具，写法是 `namespace 命名空间名 { 代码声明 }`。把相关声明收进不同命名空间，是为了避免重名冲突。

## 可见性

程序运行到某一点时，能够引用到的标识符，就是该处可见的标识符。作用域描述名字在正文中的有效区间，可见性描述在嵌套关系里此刻能不能用到这个名字。

若多个具有包含关系的作用域里声明了同名标识符，内层的声明会挡住外层：外层那个标识符在内层不可见，直到内层结束。内层结束之后，外层名字重新可见。这与后面继承里的同名隐藏是同一条可见性原则的不同场合。

## 对象的生存期

### 静态生存期

如果对象的生存期与程序运行期相同，就称它具有静态生存期。文件作用域里声明的对象都具有静态生存期，程序开始时存在，程序结束时才销毁。

函数内部的局部作用域里，也可以用关键字 `static` 让所声明的对象获得静态生存期。这样的局部静态对象只在函数初次被调用时初始化，后续每次调用都共用同一块内存，不会重新构造一份。

用 `static` 修饰类成员时，含义是该成员为该类的所有对象所共有，而不是某个具体对象私有的一份拷贝。静态数据成员本身仍然具有静态生存期。

### 动态生存期

其余对象都具有动态生存期。局部作用域中声明、又没有写成 `static` 的对象具有动态生存期，习惯上也称作局部生存期对象。局部生存期诞生于声明点，结束于声明所在块执行完毕之时；每次进入该块都会得到新的对象，离开块后对象消失。

### 类的静态成员

静态数据是类的属性：它为整个类所共有，不属于任何一个具体对象，用 `static` 关键字在类内声明。静态数据成员具有静态生存期，在程序开始时就存在，不随某个对象的构造或析构而生灭。类内的 `static` 数据成员只是声明，必须在类外给出定义（定义处不能再写 `static`），否则链接阶段会找不到符号：

```cpp
class Example {
    static int val; // 仅声明，不分配存储
};
int Example::val = 10; // 必须在类外定义，此处不能加 static
```

定义与访问是两条独立的规则：定义负责分配存储并给出初值；访问则通过类名或对象名使用已经定义好的成员。

静态成员函数可以直接访问该类的静态数据成员和静态函数成员。若要访问非静态成员，必须通过对象名，因为静态成员函数没有 `this` 指针，无法知道“当前是哪一个对象”：

```cpp
class Example {
    static int val1;
    int val2 = 5;
public:
    static void func() {
        // cout << val1; // 合法：静态成员
        // cout << val2; // 错误：不能直接访问非静态成员
    }
};
int Example::val1 = 10;
```

类的静态成员函数属于整个继承体系，不绑定到某一个派生类对象上；经基类或派生类的名字都可以调用，处理的仍是那一份类级数据。

## 类的友元

友元关系提供了不同类（或对象）的成员函数之间、以及成员函数与一般函数之间的数据共享：被授权的一方可以访问本应私有或保护的成员，但友元本身并不因此变成成员。

### 友元函数

友元函数是在类中用关键字 `friend` 修饰的非成员函数。它在类内声明，却不是该类的成员函数，本质是授权允许这个函数访问类的私有和保护成员。函数体中可以通过对象名访问这些成员。表征方式是在类内的函数声明前加上 `friend`。

正因为友元函数不是成员，不能通过 `this` 去调用它：

```cpp
class Example {
private:
    int val = 10;
    friend void friendfunc(Example &obj); // 声明友元，它仍是全局函数
public:
    void func() {
        // this->friendfunc(*this); // 错误：friendfunc 不是成员函数
    }
};
void friendfunc(Example &obj) {
    std::cout << obj.val;
}
```

若一组重载函数里只有某一个被声明为友元，授权只针对那一个特定重载版本，并不会自动覆盖所有同名重载。

### 友元类

一个类可以将另一个类声明为友元类。若在 `B` 中写 `friend class A;`，则 `A` 的所有成员函数都是 `B` 的友元函数，都可以访问 `B` 的私有和保护成员，写法形如 `class B { ... friend class A; ... };`。

反过来并不成立。在类型 `A` 中声明 `friend class B`，是 `A` 授权允许 `B` 访问 `A` 的私有成员，并不表示 `A` 也能访问 `B` 的私有成员：

```cpp
class B; // 前置声明
class A {
    int valA = 10;
    friend class B; // A 授权 B 访问自己的私有成员
public:
    void accessB(B& b) {
        // std::cout << b.valB; // 错误：A 不是 B 的友元
    }
};
class B {
    int valB = 20;
public:
    void accessA(A &a) {
        std::cout << a.valA; // 合法：B 是 A 的友元
    }
};
```

友元关系不能传递：`A` 是 `B` 的友元、`B` 是 `C` 的友元，并不使 `A` 成为 `C` 的友元。友元关系是单向的，不是对称的：`B` 是 `A` 的友元，并不推出 `A` 是 `B` 的友元。友元关系也不可继承：基类的友元不会自动成为派生类的友元。

## 共享数据的保护

### 常对象

常对象必须进行初始化，而且不能被更新。声明为 `const` 的类对象在整个生存期内保持构造时的状态；对它只能调用常成员函数，不能调用会改写对象状态的非常成员函数。非 `const` 对象则既可以调用常成员函数，也可以调用非常成员函数。

### 常成员函数

常成员函数有两处 `const` 需要同时记住：返回类型可以是 `const`（表示返回值不可改），以及参数表之后再写一个 `const`（表示该函数成员承诺不修改 `*this` 的可改状态）。完整形态是：

`const 类型 函数名(参数表) const;`

参数表后的 `const` 修饰的是函数本身，例如 `void func() const { return; }`。常成员函数里不能给非 `mutable` 的数据成员赋值，也不能调用非常成员函数。

### 常数据成员

常数据成员用 `const` 修饰，必须在构造函数的初始化列表中完成初始化，不能在构造函数体里赋值，因为进入函数体时成员已经完成初始化：

```cpp
class Example {
    const int val;
public:
    // Example() { val = 10; } // 错误：此时 val 已初始化，无法再赋值
    Example() : val(10) {}     // 只有初始化列表能初始化 const 成员
};
```

### 常引用

常引用所引用的对象不能通过该引用被更新，写法是 `const 类型 &引用名;`。非常引用只能绑定普通的（非常）对象；常引用既可以绑定常对象，也可以绑定普通对象。`const` 引用可以绑定任意对象，绑定后无法通过这条引用修改；它还支持隐式转换（转换可能产生临时对象再绑到常引用上），非 `const` 引用不行：

```cpp
double d = 3.14;
const int &ref1 = d; // 合法：允许隐式转换后绑定常引用
// int &ref2 = d;    // 错误：非 const 引用不能绑定临时对象
```

常量只能由常量指针来指向，由常引用来引用。参数里的 `const` 引用或 `const` 指针限制函数修改实参；返回值里的 `const` 引用或 `const` 指针限制调用方修改原对象。

指针与 `const` 的几种写法不可混为一谈：

| 写法 | 不可修改的对象 |
| :--- | :--- |
| `const int *ptr` 或 `int const *ptr` | 不可修改指向的对象（`*p`） |
| `int * const ptr` | 不可修改 `ptr` 的指向（`ptr` 本身） |
| `const int * const p` | 指向与指向的对象均不可修改 |

## 多文件结构与编译预处理

### 程序的一般组织结构

通常一个项目至少分为三个文件：放类定义的头文件（`*.h`）、放成员函数实现的源文件（`*.cpp`），以及使用该类的源文件（另一个 `*.cpp`，往往含 `main`）。一般将需要分配空间的定义放在源文件里；将不需要分配空间的声明、类定义放在头文件里。内联函数是例外：需要被多个编译单元调用的内联函数应出现在头文件中，以便每个翻译单元都能看到函数体并完成内联。

### 外部变量与外部函数

如果变量还能被其他文件使用，就称这个变量是外部变量。文件作用域中定义的变量，默认情况下都是外部变量。其他文件中如果需要使用这一变量，必须用 `extern` 关键字加以声明（声明不分配新的存储，只是引入已有对象）。

所有在类之外声明的函数，若没有特殊声明，都具有文件作用域。在调用前进行引用性声明之后，这些函数可以在不同编译单元被调用。这种引用性声明可以不加 `extern`，函数本身默认就是外部链接。

若要把变量和函数限制在本编译单元内、不让别的文件看见，使用 `static` 修饰文件作用域的变量和函数。这里的 `static` 与 `extern` 起相反作用：`extern` 把名字导出给其他翻译单元，`static` 把名字锁在本翻译单元。

### 标准 C++ 库

在 C 语言中，系统函数、系统的外部变量和一些宏定义都放置在运行库中。C++ 的库在此基础上还加入了预定义的模板和类。标准 C++ 类与组件在逻辑上分为：输入输出类；容器类与 ADT 类；存储管理类；算法；错误处理；运行环境支持。使用标准库时，需要引入指定的命名空间 `std`。

### 编译预处理

`#include` 是包含指令，作用是将另一个源文件嵌入当前源文件中该指令所在的位置。`#include <fileName>` 按标准方式搜索，文件位于系统目录的 `include` 子目录下。`#include "fileName"` 首先在当前目录中搜索，若没有，再按照标准方式搜索。

`#define` 做宏定义，`#undef` 删除已经定义的宏。

条件编译指令限定程序中的某些内容只有在满足一定条件时才参与编译。常用形态包括 `#if` … `#elif` … `#else` … `#endif`。`#ifdef` 表示如果标识符已经被定义过；`#ifndef` 表示如果标识符没有被定义过。二者常与头文件包含守卫一起使用，避免同一头文件被重复展开。

`defined` 是预处理运算符而不是指令。`defined(标识符)` 在该标识符曾被 `#define` 定义过、且未经 `#undef` 删除时为真，否则为假。它可以写在 `#if` 的条件里，用来组合更复杂的判断。

## 常成员函数的声明原则

不会改变对象状态的函数应声明为常成员函数，这样常对象才能调用它们，接口也把“只读”这一承诺写进类型里。会改变成员状态的函数不能声明为常成员函数。这里的“成员状态”不只有非静态数据成员的值：凡是会改写对象可观察状态的操作（包括通过指针间接改写、调用非常成员函数等）都不应当标成 `const`。

## 易错点

类内 `static` 数据成员必须在类外定义，定义处不能再写 `static`。静态成员函数没有 `this`，不能直接访问非静态成员。函数里的 `static` 局部变量只在第一次调用时初始化，以后共用同一块内存。

`const` 写在 `*` 左边还是右边，决定锁住的是对象还是指针本身，见上一节的表。常引用允许隐式转换，非常引用不能绑到转换产生的临时量上。`const` 对象只能调用常成员函数。友元类的授权是单向的：`friend class B` 写在 `A` 里只让 `B` 访问 `A`，并不让 `A` 访问 `B`。友元函数在类内声明，但不是成员，不能写成 `this->friendfunc(...)`。
